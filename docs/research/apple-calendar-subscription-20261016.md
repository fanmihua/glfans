# Apple 日历本机订阅验证（2026-10-16）

范围：用户授权在这台 Mac 的 Apple 日历测试持续订阅。下文前半部分记录正式功能发布前的本机验证；该阶段的测试数据位于 `output/apple-calendar-test-20261016/`，不改正式排期。当天正式上线与移动端反馈另记于文末。

## 测试配置

- 固定地址：`http://127.0.0.1:4187/glfans-test.ics`，只监听本机。
- 订阅名称：`glfans 订阅测试（本机临时）`；保存于“我的 Mac”，自动刷新“每 5 分钟”。
- 提醒与附件移除，“忽略提醒”开启。没有邀请参会人或读取其他日历数据。
- HTTP 不安全连接提示由用户手动点击“继续”。正式功能应使用 HTTPS。
- 用《镇灵》4 条已收录排期作为样本，每条标题均注明订阅测试；新增模拟条目明确标为“非真实排期”。
- 同一集跨阶段保持 UID。第 8 集只有日期，在 Apple 日历显示为全天；已知时刻按北京时间显示。未推断播出时长。

时间均为北京时间。阶段及请求的原始 UTC 时间记录在 `output/apple-calendar-test-20261016/stages.jsonl` 与 `requests.jsonl`。服务日志不记录请求者 IP、User-Agent、Cookie 或其他日历内容。

Apple 日历的已打开搜索结果会保留旧时间或旧条目，即使月历已更新；清空并重新输入 `glfans` 后结果正确。验收同时核对了原生月历与重新搜索后的列表。

验证结束时保留这个明确标注的本机临时订阅和本地服务，便于继续查看；feed 已恢复基线。它仅在这台电脑、本地服务运行时可访问，不是公开生产订阅。

## 正式功能需要补齐

1. 线上固定 HTTPS 地址、正确 MIME 类型、稳定 ETag 与条件请求；发布和重启后地址持续有效。
2. 订阅范围规则：全部剧集、单剧、CP 或选定剧集；范围和语言需要记录在 URL 或服务器。当前浏览器的关注列表不会被 Apple 日历自动读取。
3. 将 feed 生成接入已核实排期的发布流程，生成失败保留上个有效版本；内容不变时保持内容、修订时间和 ETag 不变。
4. 同一集改期保留 UID，DTSTAMP 对应真实修订；明确取消、待核实及历史排期的保留策略。当前按月一次性导出的筛选逻辑不能直接作为长期订阅范围。
5. 客户端按自己的周期拉取，不能承诺即时到达；本机测试结果不代表 iPhone、Google Calendar 或 Outlook 已通过测试。

参考：[Apple 订阅日历](https://support.apple.com/en-am/guide/calendar/icl1022/mac)、[Apple 刷新日历](https://support.apple.com/en-euro/guide/calendar/icl1024/mac)、[RFC 5545 UID](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.4.7)、[RFC 5545 DTSTAMP](https://www.rfc-editor.org/rfc/rfc5545.html#section-3.8.7.2)。
